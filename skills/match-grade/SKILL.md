# Единый грейд

Лук один на весь фильм, а клипы разной яркости: у каждого клипа свои `eq=gamma:contrast` до общего лука. Гамму и контраст подбирает решатель по замеру после всей цепочки; глаз только проверяет.

В командах ниже `PY` = `${LEO50S_HOME:-$HOME/.cache/leo50s-montage}/venv/bin/python`, `D` = папка этого навыка (печатается при загрузке), `T` = путь к `trailer.json`. Shell не хранит переменные между вызовами: подставляй полные пути в каждую команду. Нет venv ⇒ `bash $D/../../scripts/setup_env.sh --no-whisper`.

## Результат работы (контракт)

1. Разведка: `$PY $D/../trailer-build/scripts/probe_clips.py <папка клипов>` → из вывода нужны только раскадровки `<папка>/_probe/`: посмотри через Read, какие клипы — одна сцена.
2. В `T` есть `clips` и `look` (`noir` по умолчанию; луки — `references/looks/looks.md`). `grade` до первого решения не ставь: загрузка упадёт. Проекта нет ⇒ у всех трёх скриптов вместо `$T` — `--clips a=<путь> b=<путь> [--look noir]`, у сетки и рендера ещё `--grade <папка>/gammas.txt`; без `--out` всё ложится в текущую папку.
3. Решение: `$PY $D/scripts/solve_grade.py $T` → таблица и `gammas.txt` рядом с `T`. Пропиши в `T` `"grade": "gammas.txt"`. `before` — замер после лука при 1.0/1.0; шкалы — в `looks.md`.
4. Проверка глазом: `$PY $D/scripts/preview_grid.py $T --t 4` → `out/grade_grid.jpg`, исходник сверху, грейд снизу. Открой через Read. Тени не провалены, света не выбиты, цвета нет, есть настоящий чёрный (картинка не молочная), клипы одной сцены одинаково плотные. Плохой кадр ⇒ `--t 8`.
5. Картинка молочная (решатель дал тёмной сцене контраст < 1) или сцены должны различаться плотностью ⇒ фиксированный контраст, флаг на каждый клип: `$PY $D/scripts/solve_grade.py $T --contrast c2=1.0 --contrast c5=1.0`. Решается только гамма. Обычно 0.85–1.25, в `noir` тёмной сцене не ниже 1.0; у светлой сцены решатель может дать меньше 0.85, это нормально; итог виден в `after std`. Затем снова шаг 4.
6. По запросу полные копии со звуком: `$PY $D/scripts/render_graded.py $T` → `graded_<лук>/<имя>_<лук>.mp4` (алиас не равен имени файла ⇒ `<алиас>_<лук>_<имя>.mp4`).
7. Трейлер уже собирался ⇒ пересобери картинку, один шаг за вызов: `$PY $D/../trailer-build/scripts/build.py $T segments`, затем тем же скриптом `assemble`, `mux`, `preview`.

## Готово, когда

- solve_grade вышел с кодом 0: средняя яркость каждого клипа после грейда в ±2 от цели (82 из 255 по умолчанию, `--target-mean`). Строка `warning:` — не готово: проверь клип в сетке, ослабь его фиксированный контраст.
- Сетка после последнего решения открыта через Read.
- Сменился лук или контраст ⇒ решение заново: старые гаммы к новой кривой не подходят.

## Отдаёшь

1. `gammas.txt` и строку `"grade"` в `trailer.json`.
2. Таблицу solve_grade.
3. `out/grade_grid.jpg` и что на ней видно.
4. Копии из render_graded, если просили.
5. Допущения отдельным абзацем: какой контраст зафиксирован и почему.

## Красные флаги

- Гамма подобрана на глаз или вписана руками в `gammas.txt`.
- «Выглядит ровно», а таблицы solve_grade в ответе нет.
- `eq=gamma` дописан в файл лука.
- После смены лука сегменты пересобраны со старым `gammas.txt`.
